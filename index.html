01The 30-second idea

Most people use big chat AIs (ChatGPT, Claude…) for everything. That's like hiring a professor to tick checkboxes. It works, but it's slow and pricey, and the answer comes back as a paragraph your app has to untangle.

Jev is a different kind of AI. It doesn't write. You ask short questions, and it answers with a number or a pick from a list, ready for your code.

flowchart LR A["📄 Your data (state)"] --> C{{"⚡ Jev · ~100 ms"}} B["❓ Your questions"] --> C C --> D["🔢 Typed answers + probabilities"] D --> E["💻 Your code decides"]

02The 3 tools you'll use

Every Jev question is one of these three types. That's all there is to learn.

ToolYou askYou getExample
🗂️ Choice"Pick ONE from this list"the pick + % per option + confidenceWhich team handles this ticket?
🎚️ Noul"Is this true?"probability 0 (no) → 1 (yes)Does the customer want a refund?
📏 Score"Where on this ladder?"position on your levels (e.g. 1.4) + confidenceHow angry is the customer?
💬 A Noul of 0.5 means "can't tell", not "medium". For "how much", use Score.

03Step by step: your first app

We'll build a support-ticket sorter: it reads a customer message and decides the team, the urgency, and whether to flag a refund.

flowchart LR S1["1 Sign up"] --> S2["2 Playground"] --> S3["3 API key"] --> S4["4 Install"] --> S5["5 One call"] --> S6["6 Code decides"] --> S7["7 Test & tune"] --> S8["🚀 Ship"]

  1. Sign up

    Go to console.typesafe.ai and continue with Google or email.

  2. Play first, with no code

    Open the Playground. Paste a message as the state:

    Hi, I've been trying to connect my Stripe account for 3 days and the integration keeps failing. I'm losing sales. Please help ASAP.

    Add a noul question: Does this message express urgency?. Then add a Choice and a Score and watch all the answers come back together.

    🎯 Reword your questions here until the answers look right. It's the cheapest place to experiment.

  3. Get an API key

    Dashboard → Keys. Then:

    export TYPESAFE_API_KEY="paste-your-key-here"
    🔒 Never put the key in website or mobile frontend code. Call TypeSafe from your server.

  4. Install

    # Python 3.10+
pip install typesafe-sdk

# JavaScript / TypeScript (Node 20+)
npm install @typesafe-ai/sdk

  5. Ask everything in ONE call

    from typesafe_sdk import Choice, Noul, Score, TypeSafeClient

with TypeSafeClient() as client:
    r = client.system_one(
        state={"ticket": "I was charged twice. Please fix this ASAP."},
        questions={
            "team": Choice(
                instructions="Which team should handle this ticket?",
                criteria={
                    "billing": "Payment or subscription issues",
                    "technical": "Bugs or integration problems",
                    "other": "None of the above",
                },
            ),
            "urgent": Noul(instructions="The message conveys urgency."),
            "frustration": Score(
                instructions="How frustrated does the customer appear?",
                criteria=["Calm", "Frustrated but civil", "Very angry"],
            ),
        },
        model="jev-latest",
    )

    A real sample answer from the docs:

    "department":  { "choice": "technical", "confidence": 0.78,
                 "probabilities": { "technical": 0.85, "billing": 0.15, "sales": 0.0 } }
"frustration": { "score": 1.0, "confidence": 1.0 }
"is_urgent":   { "noul": 1.0 }

  6. Let code make the decision

    team = r.choices["team"]
queue = team.choice if team.confidence >= 0.5 else "human-review"
priority = "P1" if r.nouls["urgent"].noul > 0.8 else "P2"

    The AI gives evidence (numbers), and your code sets the rules. You can change a rule any time without paying for new AI calls. Full example: examples/support_triage.py.

  7. Test, tune, ship

    Run 20–50 real messages. Where it's wrong, reword the question or make the option descriptions clearer. Pick thresholds from your results, not guesses.

04The 7 golden rules for low cost + high speed

Rule 1: 📦 One envelope, many questions (the biggest saving)

Your data (the "state") is usually the expensive part. 13 questions in 13 calls means paying for the data 13 times. Put them all in one call and you pay once.

Rule 2: 💻 If plain code can do it, don't use AI

flowchart LR Q{"Can a simple rule or lookup do it?"} -->|Yes| C["💻 Plain code · $0"] Q -->|No| Q2{"Is the answer a pick, yes/no, or a level?"} Q2 -->|Yes| J["⚡ Jev · tiny cost"] Q2 -->|"No, needs writing / deep reasoning"| L["🧑‍🏫 Big LLM · highest cost"]

Rule 4: 🪜 Cheap first, expensive only if needed

📦1 · Batch questions

All questions about the same data go in one call.

💻2 · Code first

Math, dates, lookups, rules cost $0. Use AI only for understanding.

👉3 · Pick, don't write

Code finds candidates (every date in an email), and Jev picks the right one. It's cheaper and can't invent values.

🪜4 · Cheap → check → escalate

A cheap model does the work, Jev checks it, and only doubtful cases go to the big model.

✂️5 · Send only what's needed

Named fields like {"ticket":…,"policy":…}, not your whole database.

💾6 · Score once, reuse

Save raw numbers. New weights or filters later need no new AI calls.

🚦7 · Confidence = traffic light

🟢 act · 🟡 act & log · 🔴 human or bigger AI. Expensive help only on hard cases.

08Mistakes to avoid

❌ Don't✅ Do
One huge vague question ("Is this good?")Small clear ones ("Is it polite?", "On-topic?")
One call per questionBatch them all in one call
Treat Noul 0.5 as "medium"0.5 = can't tell. Use Score for "how much"
Forget a "none of these" optionAdd other / none
API key in frontend codeCall TypeSafe from your server
Copy thresholds from examplesTune on your own real data
Big LLM for sorting / checkingJev; keep the big LLM for writing

09Cheat sheet

CODE  does steps & rules        → $0
JEV   makes quick judgments     → tiny $, ~100 ms
LLM   writes / reasons deeply   → $$$, use rarely
